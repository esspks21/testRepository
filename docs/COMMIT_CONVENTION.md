# Commit Convention

## 커밋 메시지 구조

```
<type>(<scope>): <subject>

<body>

<footer>
```

---

## Type (타입)

| 타입 | 설명 |
|------|------|
| `Feat` | 새로운 기능 추가 |
| `Fix` | 버그 수정 |
| `Docs` | 문서 추가 / 수정 |
| `Style` | 코드 포맷팅, 세미콜론 누락 등 (기능 변경 없음) |
| `Refactor` | 코드 리팩토링 (기능 변경 없음) |
| `Test` | 테스트 코드 추가 / 수정 |
| `Chore` | 빌드 설정, 패키지 업데이트 등 기타 변경 |

---

## Scope (범위)

변경이 영향을 미치는 범위를 소괄호 안에 작성합니다. (선택 사항)

예시: `feat(auth)`, `fix(api)`, `docs(readme)`

---

## Subject (제목)

- 50자 이내로 작성
- 마침표 없이 작성
- 명령형 현재 시제 사용 (예: "변경한다", "추가한다")

---

## Body (본문)

- 72자마다 줄바꿈
- 무엇을, 왜 변경했는지 작성
- 선택 사항

---

## Footer (푸터)

- 이슈 번호 참조 시 작성 (예: `Closes #123`)
- Breaking Change가 있을 경우 명시
- 선택 사항

---

## 예시

```
feat(auth): 소셜 로그인 기능 추가

Google, Kakao OAuth 로그인을 지원합니다.
기존 이메일 로그인과 병행 사용 가능합니다.

Closes #42
```

```
fix(api): 사용자 조회 시 null 반환 오류 수정
```

```
docs(readme): 프로젝트 실행 방법 업데이트
```
